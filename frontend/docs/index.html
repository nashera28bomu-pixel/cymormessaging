Cymor Messaging API

The Cymor Developer API lets you send WhatsApp messages, manage contacts, and receive delivery events from your own backend. All requests are authenticated with an API key and versioned under /v1.

Quick start

curl -X POST https://api.cymormessaging.com/v1/messages \
  -H "X-API-Key: cym_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "whatsAppAccountId": "665f...",
    "to": "2547XXXXXXXX",
    "type": "text",
    "text": { "body": "Hello from Cymor!" }
  }'

Authentication

Every request must include an X-API-Key header. Create a key from Dashboard → Developer → API keys. Keys are shown once at creation time.

X-API-Key: cym_live_ab12cd34ef...

Sending messages

MethodPathDescription
POST/v1/messagesSend a text, template, image, document, audio, video, or interactive message
GET/v1/messagesList messages (cursor-paginated)
GET/v1/messages/:idFetch a single message
// JavaScript
const res = await fetch("https://api.cymormessaging.com/v1/messages", {
  method: "POST",
  headers: { "X-API-Key": apiKey, "Content-Type": "application/json" },
  body: JSON.stringify({
    whatsAppAccountId, to: "2547XXXXXXXX",
    type: "text", text: { body: "Hello!" }
  })
});

Receiving messages

Register a webhook (see below) subscribed to message.received to get inbound customer messages pushed to your backend in real time, instead of polling.

Templates

GET /v1/templates lists templates and their current Meta approval status (PENDING, APPROVED, REJECTED, etc). Only APPROVED templates can be sent.

OTP

MethodPath
POST/v1/otp/send
POST/v1/otp/verify

Codes expire after 5 minutes and allow 5 verification attempts. Resends are limited to once every 60 seconds per phone number.

Webhooks

Subscribe your own URL to platform events. Every delivery includes an X-Cymor-Signature header — an HMAC-SHA256 of the raw body, signed with the secret shown when you create the webhook.

{
  "event": "message.received",
  "data": { "conversationId": "...", "message": { ... } },
  "timestamp": "2026-08-12T10:00:00.000Z"
}

Campaigns

Campaigns are created and started from the dashboard today. Each recipient is processed as an independent queue job, so a campaign to 50,000 contacts never blocks and a single failed send never affects the rest.

Rate limits

The public API is limited to 120 requests/minute per API key. OTP endpoints are limited to 5 requests/minute per key. Exceeding a limit returns 429 with a RATE_LIMITED error code.
